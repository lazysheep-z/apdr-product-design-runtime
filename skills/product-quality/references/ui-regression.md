# UI 与增量原型回归

## 基线和修改

- 用户当前明确要求优先；先读项目规则、现有设计规范和本次指定文件。并行编辑时比较当前哈希，不用旧副本覆盖新修改。
- 巨型单文件按导航、组件、模板、事件和样式入口定位，先建立小范围地图，再做精确修改；不要仅靠末尾 CSS 覆盖掩盖状态同步问题。
- 修改后核对最终交付文件的 SHA-256 与被测版本。共用主题、日期、筛选或路由修改要检查所有受影响入口，包括缓存页签往返和浏览器导航。

## 组件和可读性

- 统一批准的字体、字号、间距、表格密度、对齐、按钮与弹层样式；检查实际渲染的第三方控件、SVG、Canvas 图表与全屏状态。
- 图表分类色使用稳定映射，跨页/排序/筛选后不漂移；色板数量覆盖分类，图例和表格一致。目标/基准线与实际系列语义分开，不强制固定色数、配色或业务分类。
- 主按钮检查默认、禁用、加载、恢复启用、提交成功/失败状态；避免一次性对比度脚本在状态切换后留下错误颜色。
- 桌面、平板、手机和最窄支持宽度按交付范围验证。长金额、长名称、密集分类、KPI 卡片、固定首列和宽表应保持可读；检查表格内部滚动与整页溢出，不能只看文档宽度。

## 交互和可访问性

- 日期/筛选弹层检查边界、裁切、滚动、翻月、焦点保持、取消/确认/Esc；模态面板管理焦点并关闭后返回触发器，非模态下拉遵循对应语义。
- 检查图标按钮名称、页签结构、嵌套可交互元素、键盘可达、横向滚动容器、触控热区、对比度与错误提示。错误说明应可理解、可定位、可恢复。
- 自动扫描覆盖主页面及实际打开的弹层/编辑状态；分别统计 violations 和 incomplete，保留人工判断。工具零违规不等于所有状态通过或完整标准认证。
- 页面打开、点击有反馈、toast 成功都不足以证明数据已保存、文件已生成或后台已完成。
